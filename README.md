Система управления базой данных студентов

Данная программа представляет собой простую систему управления базами данных (СУБД), которая поддерживает два режима хранения информации: в оперативной памяти (in-memory) и в файлах формата JSON. Программа предназначена для хранения и управления информацией о студентах, но также позволяет создавать произвольные таблицы с любым набором колонок. Пользователь может создавать таблицы для хранения данных, добавлять новые записи, просматривать все записи, искать нужные записи по различным критериям, обновлять информацию, удалять записи и сортировать записи по любому полю. При использовании файловой реализации все данные сохраняются на диск в папку data и не теряются после закрытия программы, в то время как in-memory реализация хранит данные только в оперативной памяти и теряет их при завершении работы. Это делает программу удобной как для тестирования и обучения, так и для практического использования с сохранением данных между запусками.

Программа реализована с использованием объектно-ориентированного подхода и принципов полиморфизма. Основные компоненты программы расположены в папке backend и включают в себя несколько ключевых файлов. Файл table.py содержит класс Table, который отвечает за хранение данных одной таблицы и предоставляет методы для вставки, выборки, обновления, удаления и сортировки записей. Файл memory.py содержит класс MemoryDatabase, который реализует in-memory базу данных, управляет несколькими таблицами и предоставляет интерфейс для работы с ними, а также содержит функции для обратной совместимости с первой лабораторной работой - create_record, select_record, init_student_table и класс Student. Файл database.py содержит абстрактный класс Database, который задаёт единый интерфейс для всех реализаций базы данных и определяет методы create_table, insert_record, select_records, update_records и delete_records. Файл file.py содержит класс FileDatabase, который наследуется от Database и реализует файловое хранение данных в формате JSON, где каждая таблица сохраняется в отдельный файл в директории data. Файл errors.py содержит пользовательские исключения для обработки ошибок, такие как TableAlreadyExistsError при создании уже существующей таблицы, TableNotFoundError при обращении к несуществующей таблице, MissingColumnError при отсутствии обязательного поля в записи, UnknownColumnError при использовании неизвестного поля, InvalidStorageDataError при чтении повреждённых данных из файла, InvalidAgeError при попытке создать запись с отрицательным возрастом и DuplicateIDError при попытке создать запись с дублирующимся идентификатором.

Пользовательский интерфейс реализован в файле tui.py и представляет собой консольное меню с командами для выполнения всех операций. При запуске программы пользователю предлагается выбрать тип базы данных: in-memory (данные не сохраняются) или файловая JSON (данные сохраняются в папке data). После выбора отображается главное меню с десятью пунктами от 0 до 9. Команда 1 позволяет создать новую таблицу, указав её имя и список колонок, причём можно использовать стандартные поля id, имя, фамилия, возраст, пол или задать свои. Команда 2 показывает список всех существующих таблиц с информацией о количестве записей в каждой. Команда 3 добавляет новую запись в выбранную таблицу, запрашивая значения для всех колонок. Команда 4 показывает все записи выбранной таблицы в виде форматированной таблицы. Команда 5 выполняет поиск записей по одному или нескольким критериям с точным совпадением значений. Команда 6 обновляет записи, соответствующие заданным фильтрам, изменяя указанные поля. Команда 7 удаляет записи, соответствующие заданным фильтрам, с подтверждением при удалении всех записей. Команда 8 показывает информацию о выбранной таблице, включая список колонок и количество записей. Команда 9 выполняет сортировку записей по указанному полю в порядке возрастания или убывания. Команда 0 завершает работу программы.

Точка входа в программу находится в файле __main__.py, который импортирует функцию run из модуля tui и запускает приложение. При старте программы автоматически создаётся таблица студентов со стандартными колонками id, имя, фамилия, возраст, пол, что обеспечивает обратную совместимость с предыдущими лабораторными работами.

Для работы программы требуется Python версии 3.10 или выше. Никаких дополнительных библиотек не требуется, так как используются только встроенные модули, включая json для работы с файлами, abc для создания абстрактных классов, pathlib для работы с путями и unittest для тестирования. Для запуска программы необходимо открыть командную строку, перейти в папку с проектом и выполнить команду python -m src.db. После этого отобразится приветствие с выбором типа базы данных, затем главное меню программы.

Структура проекта организована следующим образом. В корневой папке находится файл README.md с подробным описанием проекта. Папка src содержит исходный код программы. В папке src/db находятся файлы __init__.py, __main__.py и tui.py. Файл __init__.py экспортирует основные классы и функции для удобного импорта. Файл __main__.py является точкой входа и запускает приложение. Файл tui.py содержит класс DatabaseApp с реализацией текстового интерфейса. Папка src/db/backend содержит файлы __init__.py, database.py, errors.py, file.py, memory.py и table.py. Файл __init__.py экспортирует все классы бэкенда. Файл database.py определяет абстрактный класс Database. Файл errors.py определяет пользовательские исключения. Файл file.py содержит класс FileDatabase для файлового хранения. Файл memory.py содержит класс MemoryDatabase для in-memory хранения, а также функции create_record, select_record, init_student_table и класс Student для обратной совместимости. Файл table.py содержит класс Table. Папка data создаётся автоматически при использовании файловой базы данных и содержит JSON-файлы таблиц. Папка tests содержит файлы __init__.py, test_memory.py и test_file_database.py с модульными тестами, покрывающими основную функциональность. Файл test_memory.py содержит тесты для MemoryDatabase и интерфейса Student, включая тесты создания таблиц, вставки записей, выборки с фильтрами, обновления, удаления, сортировки и обработки ошибок. Файл test_file_database.py содержит тесты для FileDatabase, включая тесты сохранения данных между экземплярами, выборки с фильтрами, обновления, удаления и обработки повреждённых файлов.

Для запуска тестов необходимо установить библиотеку coverage командой pip install coverage. Затем выполнить команду coverage run -m unittest discover tests для запуска всех тестов и сбора информации о покрытии. После этого можно посмотреть отчёт о покрытии командой coverage report -m. Уровень покрытия кода тестами составляет более 80 процентов, что гарантирует надёжность работы основных компонентов системы. Для генерации HTML-отчёта с детальной информацией о покрытии можно использовать команду coverage html, после чего открыть файл htmlcov/index.html в браузере.

Основное различие между in-memory и файловой реализациями заключается в способе хранения данных. In-memory реализация хранит все таблицы и записи в оперативной памяти в виде словаря, где ключами являются имена таблиц, а значениями - объекты класса Table. При завершении программы все данные теряются, что делает эту реализацию удобной для быстрого тестирования и разработки. Файловая реализация сохраняет каждую таблицу в отдельный JSON-файл в директории data. При создании таблицы создаётся файл с именем таблицы и расширением .json, который содержит структуру таблицы в виде объекта с полями columns (список колонок) и records (список записей). При вставке, обновлении или удалении записей файл перезаписывается с новыми данными. При запуске программы данные загружаются из файлов, что позволяет продолжать работу с ранее сохранённой информацией. JSON-формат выбран для хранения данных, потому что он является человекочитаемым, легко отлаживается, поддерживается стандартной библиотекой Python и хорошо подходит для демонстрации структуры данных в учебных целях.

Программа корректно обрабатывает следующие ошибочные ситуации. При попытке создать таблицу с именем, которое уже существует, программа сообщает об ошибке TableAlreadyExistsError. При обращении к несуществующей таблице выводится предупреждение TableNotFoundError. При добавлении записи с отсутствующим полем программа сообщает, какого поля не хватает, с помощью исключения MissingColumnError. При добавлении записи с лишним полем программа сообщает, какое поле неизвестно, с помощью исключения UnknownColumnError. При попытке добавить студента с отрицательным возрастом программа выводит сообщение об ошибке InvalidAgeError. При попытке добавить студента с идентификатором, который уже существует в таблице, программа сообщает о дублировании с помощью исключения DuplicateIDError. При использовании несуществующего поля в фильтрах или сортировке программа выводит сообщение об ошибке UnknownColumnError. При попытке загрузить повреждённый JSON-файл программа возбуждает исключение InvalidStorageDataError с понятным сообщением. Все ошибки обрабатываются на уровне пользовательского интерфейса, который выводит понятные сообщения и позволяет пользователю продолжить работу без аварийного завершения программы.

Данная лабораторная работа демонстрирует практическое применение принципов объектно-ориентированного программирования, включая абстракцию, инкапсуляцию, наследование и полиморфизм. Абстрактный класс Database задаёт единый интерфейс для всех реализаций, что позволяет легко добавлять новые способы хранения данных без изменения пользовательского кода. Класс Table инкапсулирует логику работы с одной таблицей, скрывая внутреннее представление данных. Классы MemoryDatabase и FileDatabase наследуются от Database и реализуют специфические методы загрузки и сохранения таблиц. Полиморфизм позволяет пользовательскому интерфейсу работать с любым типом базы данных через единый интерфейс, не заботясь о деталях реализации. Такой подход делает программу легко расширяемой и поддерживаемой, что является важным навыком при разработке реальных программных проектов.
