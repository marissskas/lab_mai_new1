Описание программы "In-Memory Database"

Данная программа представляет собой простую систему управления базами данных, которая поддерживает два типа хранения информации: оперативную память и файловую систему. Программа позволяет пользователю создавать таблицы для хранения данных, добавлять в них записи, просматривать все сохранённые сведения, искать нужные записи по одному или нескольким критериям, изменять и удалять существующие записи, а также сортировать их по любому полю в порядке возрастания или убывания. Главное отличие от предыдущей версии заключается в том, что теперь данные можно сохранять на диск, благодаря чему они не теряются после закрытия программы.

Архитектура программы
Программа реализована с использованием объектно-ориентированного подхода, а ключевым архитектурным решением стало введение абстрактного класса Database, который задаёт единый интерфейс для всех способов хранения данных. Это означает, что независимо от того, работаете ли вы с оперативной памятью или с файлами, набор доступных команд остаётся одинаковым. Такой подход позволяет легко переключаться между разными реализациями без изменения остального кода.

Код организован в несколько модулей. В папке backend располагаются основные компоненты: абстрактный класс database.py, определяющий общий интерфейс; memory_db.py, отвечающий за хранение данных в оперативной памяти; file_db.py, реализующий файловое хранение в формате JSON; table.py, описывающий структуру отдельной таблицы и правила работы с её записями; и errors.py, содержащий набор пользовательских исключений для обработки ошибок. Пользовательский интерфейс вынесен в отдельный модуль tui.py, а точка входа в программу находится в файле main.py.

Типы баз данных
При запуске программы пользователю предлагается выбрать один из двух режимов работы.

Первый режим — in-memory база данных. В этом случае все таблицы и записи хранятся исключительно в оперативной памяти. Такой вариант обеспечивает максимальную скорость работы, но имеет существенный недостаток: после завершения программы все данные безвозвратно теряются. Этот режим удобен для тестирования или для работы с временной информацией, которая не требует долгосрочного хранения.

Второй режим — файловая база данных. Здесь каждая таблица сохраняется в отдельный JSON-файл в специальной папке data. При следующем запуске программа автоматически загружает все ранее созданные таблицы и их записи. Данные остаются доступными даже после перезагрузки компьютера. Скорость работы в этом режиме несколько ниже из-за необходимости обращаться к диску, однако это оправдано надёжностью хранения.

Функциональные возможности
Программа предоставляет полный набор операций для управления данными, известный как CRUD (создание, чтение, обновление, удаление).

Создание таблицы начинается с выбора соответствующего пункта меню. Пользователь вводит имя новой таблицы и перечисляет названия колонок через пробел. После успешного создания таблица появляется в общем списке, и в неё можно добавлять записи.

Добавление записи требует указать значения для всех колонок таблицы. Программа проверяет, что ни одно обязательное поле не пропущено, а также что не переданы лишние поля, не предусмотренные структурой таблицы. Если всё в порядке, запись сохраняется.

Чтение записей возможно в двух вариантах. Можно просмотреть все записи таблицы целиком, а можно воспользоваться фильтрацией, указав значения для одного или нескольких полей. Например, легко найти всех студентов определённого возраста или всех пользователей с заданным именем. Фильтры работают по принципу точного совпадения.

Обновление записей позволяет изменять данные в уже существующих строках. Сначала пользователь задаёт фильтры, чтобы выбрать, какие именно записи нужно изменить, а затем указывает новые значения для нужных полей. Если фильтры не заданы, программа предупредит, что будут обновлены все записи, и запросит подтверждение.

Удаление записей работает по аналогичному принципу: пользователь задаёт фильтры для выбора удаляемых строк, после чего подтверждает операцию. При удалении всех записей без фильтров также требуется дополнительное подтверждение, чтобы избежать случайной потери данных.

Сортировка позволяет упорядочить записи по любому полю таблицы. Пользователь выбирает поле и направление сортировки — по возрастанию или по убыванию. Важно отметить, что сама таблица при этом не изменяется, программа лишь показывает отсортированную копию данных.

Просмотр информации о таблице даёт возможность узнать список её колонок и количество хранящихся в ней записей.

Обработка ошибок
Программа уделяет большое внимание корректной обработке ошибочных ситуаций. Вместо стандартных исключений используются собственные пользовательские исключения, которые делают сообщения об ошибках более понятными.

Если пользователь пытается создать таблицу с именем, которое уже существует, программа сообщит об этом и предложит выбрать другое имя. При обращении к несуществующей таблице будет выведено соответствующее предупреждение.

При добавлении записи программа проверяет наличие всех обязательных полей. Если какое-то поле отсутствует, операция будет отклонена с пояснением, какого именно поля не хватает. Аналогично, если передано лишнее поле, не входящее в структуру таблицы, последует ошибка.

При использовании фильтров или сортировки программа проверяет, существуют ли указанные поля в структуре таблицы. Если поле не найдено, операция не будет выполнена, а пользователь увидит сообщение о том, какое поле вызвало проблему.

В файловом режиме добавляются дополнительные проверки, связанные с чтением и записью данных на диск. Если JSON-файл повреждён или имеет неверную структуру, программа выбросит исключение InvalidStorageDataError с подробным описанием проблемы. Также обрабатываются ошибки доступа к файловой системе, например, если папка для хранения данных недоступна для записи.

Интерфейс пользователя
Программа имеет полностью текстовый интерфейс, работающий через консоль. После запуска пользователь видит приветственное сообщение и предложение выбрать тип базы данных. После выбора отображается главное меню с девятью пунктами, где каждый пункт соответствует определённой операции. Пользователь вводит цифру от нуля до девяти, после чего программа переходит к выполнению выбранного действия. Все дальнейшие шаги сопровождаются понятными подсказками. После завершения каждой операции программа возвращается в главное меню, позволяя продолжить работу.

Выход из программы осуществляется через специальный пункт меню. При использовании файловой базы данных все изменения к этому моменту уже сохранены на диск, поэтому при следующем запуске данные будут доступны в том же виде.

Тестирование
Программа покрыта автоматизированными модульными тестами с использованием фреймворка unittest. Тесты проверяют создание таблиц, все CRUD-операции, сортировку записей, обработку ошибок и работу с несколькими таблицами одновременно. Особое внимание уделено тестированию файловой реализации: проверяется, что данные действительно сохраняются между разными запусками программы, а также корректно обрабатываются ситуации с повреждёнными JSON-файлами.

Для измерения полноты тестирования используется инструмент coverage. Уровень покрытия кода тестами составляет более восьмидесяти процентов, что гарантирует надёжность работы основных компонентов системы.

Запуск всех тестов выполняется командой python -m unittest discover tests, а для просмотра отчёта о покрытии используется команда coverage run -m unittest discover tests с последующим вызовом coverage report -m.
