Проект представляет собой консольное приложение для управления in-memory базой данных студентов, разработанное в рамках лабораторной работы. Структура проекта организована следующим образом: в корневой директории находится файл run.py, который служит для запуска приложения, а вся основная логика расположена в пакете src.db. Внутри пакета db создан подпакет backend с модулем memory.py, содержащим ядро базы данных. Также в пакете db находятся файлы main.py как точка входа, tui.py с реализацией текстового пользовательского интерфейса, utils.py со вспомогательными функциями и exceptions.py с пользовательскими исключениями.

В файле exceptions.py определены четыре класса исключений, образующих иерархию. Базовый класс DatabaseError наследуется от Exception и служит основой для всех исключений базы данных. От него наследуются TableNotFoundError для ситуаций, когда запрашиваемая таблица не существует, RecordNotFoundError для случаев отсутствия записи с указанным идентификатором, и ValidationError для ошибок валидации вводимых данных. Эти исключения используются во всем проекте для единообразной обработки ошибок и предоставления понятных сообщений пользователю.

Модуль memory.py является ядром проекта и реализует основную логику работы с данными. В нем определен тип StudentRecord как кортеж из пяти элементов, представляющий запись о студенте: идентификатор, имя, фамилия, возраст и пол. Класс Table представляет отдельную таблицу в базе данных. При инициализации таблица получает имя и создает пустой словарь _records для хранения записей, где ключом выступает идентификатор студента, а значением - кортеж с данными. Также создается счетчик _counter для автоматической генерации идентификаторов.

Класс Table содержит несколько вспомогательных методов для валидации данных. Метод _validate_age проверяет, что возраст не отрицательный и не превышает 120 лет, в противном случае выбрасывает исключение ValueError. Метод _validate_name очищает имя от пробельных символов, проверяет что оно не пустое и содержит минимум два символа, после чего возвращает имя с заглавной буквы. Метод _validate_sex проверяет что пол указан как 'м' или 'ж' (с учетом английских эквивалентов M и F) и приводит его к единому формату с заглавной буквы. Метод _generate_id увеличивает внутренний счетчик и возвращает новое значение для использования в качестве идентификатора.

Метод create_record создает новую запись в таблице. Он принимает идентификатор как опциональный параметр - если он не указан, генерируется автоматически с помощью _generate_id. Затем выполняется валидация всех полей с помощью соответствующих методов, после чего проверяется уникальность идентификатора - если запись с таким ID уже существует, выбрасывается исключение. После успешной проверки создается кортеж с данными, который сохраняется в словарь _records под ключом, равным идентификатору. Метод возвращает созданную запись.

Метод select_record выполняет поиск записей по заданным фильтрам. Он принимает все поля как опциональные параметры, а также поддерживает передачу дополнительных фильтров через **kwargs. В начале работы все фильтры собираются в единый словарь all_filters, после чего проверяется наличие хотя бы одного непустого фильтра. Если фильтры не заданы, метод возвращает список всех записей. В противном случае происходит перебор всех записей с проверкой каждого условия - при несовпадении любого фильтра запись пропускается. Поиск по имени и фамилии выполняется регистронезависимо с помощью приведения к нижнему регистру, а поиск по полу также выполняется без учета регистра. Метод возвращает список записей, удовлетворяющих всем условиям.

Метод get_by_id обеспечивает быстрый доступ к записи по идентификатору. Он напрямую обращается к словарю _records и возвращает запись, если она существует, или выбрасывает исключение RecordNotFoundError с соответствующим сообщением.

Метод update_record обновляет существующую запись. Он принимает идентификатор записи и опциональные новые значения для полей. Сначала проверяется существование записи с указанным ID, затем из словаря извлекается старая запись. Для каждого поля, которое было передано, выполняется валидация нового значения, и если валидация проходит успешно, оно сохраняется для обновления. Если поле не передано, используется старое значение. После подготовки всех значений создается новый кортеж, который заменяет старую запись в словаре. Метод возвращает обновленную запись.

Метод delete_record удаляет запись по идентификатору. Он проверяет существование записи, и если она найдена, удаляет ее из словаря с помощью оператора del. В случае успеха возвращает True. Метод count возвращает количество записей в таблице, используя функцию len для словаря _records. Метод clear полностью очищает таблицу, удаляя все записи из словаря и сбрасывая счетчик _counter в ноль. Также в классе реализованы магические методы len, который позволяет использовать функцию len для получения размера таблицы, и contains, который позволяет проверять существование записи через оператор in.

Класс Database управляет коллекцией таблиц. При инициализации он создает пустой словарь _tables для хранения таблиц, где ключом является имя таблицы, а значением - объект Table. Также создается атрибут _current для хранения имени текущей выбранной таблицы.

Метод create_table создает новую таблицу. Он проверяет, что имя не пустое, и что таблица с таким именем еще не существует. В случае успеха создается новый объект Table, который сохраняется в словарь под указанным именем. Метод возвращает созданную таблицу.

Метод get_table возвращает таблицу по имени. Если таблица с указанным именем не найдена, выбрасывается исключение TableNotFoundError. Метод drop_table удаляет таблицу, предварительно проверяя ее существование. Если удаляется текущая таблица, атрибут _current сбрасывается в None.

Метод list_tables возвращает список имен всех таблиц. Метод get_tables_with_counts возвращает список кортежей, каждый из которых содержит имя таблицы и количество записей в ней - это удобно для отображения пользователю в интерфейсе. Методы set_current и get_current позволяют установить и получить имя текущей таблицы. Метод rename_table переименовывает таблицу, проверяя что старое имя существует, а новое не занято. При переименовании запись в словаре перемещается под новый ключ, и если переименовывается текущая таблица, обновляется и атрибут _current. Метод exists проверяет существование таблицы по имени.

Модуль tui.py реализует текстовый пользовательский интерфейс через класс ConsoleInterface. При инициализации создается экземпляр базы данных, атрибут current_table для хранения текущей таблицы и флаг running для управления основным циклом программы.

Класс содержит множество вспомогательных методов для работы с интерфейсом. Метод _clear_screen очищает экран консоли, используя соответствующую команду для Windows или Unix-подобных систем. Метод _print_header выводит заголовок программы с информацией о текущей таблице. Методы _print_main_menu, _print_table_menu и _print_record_menu выводят соответствующие меню с пунктами действий.

Методы ввода данных реализуют циклы с повторением до получения корректного ввода. _read_int читает целое число, с возможностью разрешить пустое значение через параметр allow_none. _read_optional_int является оберткой над _read_int для чтения опциональных чисел. _read_string читает строку с проверкой на пустое значение, если поле обязательное. _read_choice читает выбор пользователя из меню и проверяет, что введенное значение находится в списке допустимых.

Метод _print_records выводит записи в отформатированном виде. Если список записей пуст, выводится сообщение об отсутствии записей. Иначе для каждой записи выводится строка с ID, именем, фамилией, возрастом и полом, а в конце выводится общее количество записей.

Метод _handle_tables реализует цикл обработки меню таблиц. Он отображает меню, получает выбор пользователя и вызывает соответствующие методы. Доступны действия: создание таблицы, выбор таблицы, просмотр списка таблиц, переименование таблицы, удаление таблицы и очистка таблицы. Все операции обернуты в try-except для обработки исключений базы данных.

Метод _handle_records аналогично обрабатывает меню записей, но сначала проверяет, что выбрана таблица. Если таблица не выбрана, выводится сообщение и происходит возврат в главное меню. Доступны действия: добавление записи, просмотр всех записей, поиск по ID, расширенный поиск, обновление записи и удаление записи.

Метод _create_table запрашивает имя новой таблицы и создает ее через объект базы данных. Метод _select_table показывает список доступных таблиц с количеством записей, позволяет выбрать по номеру или имени, и устанавливает выбранную таблицу как текущую. Метод _list_tables показывает все таблицы с количеством записей, отмечая текущую таблицу стрелочкой. Метод _rename_table запрашивает текущее и новое имя таблицы и выполняет переименование. Метод _drop_table запрашивает имя таблицы и после подтверждения удаляет ее. Метод _clear_table очищает указанную таблицу после подтверждения, показывая количество записей, которые будут удалены.

Метод _create_record создает новую запись. Он информирует пользователя о возможности автоматической генерации ID, затем запрашивает все поля. ID запрашивается как опциональное значение - если пользователь оставляет поле пустым, будет использована автоматическая генерация. После ввода всех данных вызывается метод create_record таблицы, и в случае успеха выводится информация о созданной записи.

Метод _show_all_records выводит все записи текущей таблицы, используя метод select_record без фильтров. Метод _find_by_id запрашивает ID и выводит запись с указанным идентификатором, если она существует. Метод _advanced_search реализует расширенный поиск с возможностью комбинировать несколько фильтров. Пользователь может заполнить любое количество полей, пустые поля игнорируются. Все введенные фильтры собираются в словарь и передаются в метод select_record через **kwargs.

Метод _update_record обновляет существующую запись. Сначала запрашивается ID записи, затем показываются текущие данные. После этого пользователь может ввести новые значения для любых полей, оставляя пустые поля без изменений. Все введенные обновления собираются в словарь и передаются в метод update_record. Метод _delete_record удаляет запись после подтверждения, предварительно показывая данные удаляемой записи.

Метод run является основным циклом программы. Он отображает главное меню, получает выбор пользователя и вызывает соответствующие обработчики. Цикл продолжается пока флаг running истинен. Также обрабатывается исключение KeyboardInterrupt для корректного выхода при нажатии Ctrl+C.

Модуль utils.py содержит вспомогательные функции, которые могут использоваться в разных частях проекта. Функция parse_filters разбирает строку фильтров вида "поле=значение,поле=значение" и возвращает словарь с фильтрами. Она автоматически преобразует числовые значения в соответствующие типы (int или float). Функция print_records выводит записи с заголовком и форматированием, аналогично методу _print_records в tui.py. Функция read_int реализует безопасное чтение целого числа с повторением при ошибке. Функция read_optional_int читает опциональное целое число, возвращая None при пустом вводе. Функция read_optional_float аналогично читает опциональное число с плавающей точкой. Функция read_string читает строку с возможностью проверки на пустое значение.

Модуль main.py является точкой входа в приложение. Он содержит функцию main, которая создает экземпляр ConsoleInterface и запускает его метод run. При запуске модуля как скрипта вызывается функция main.

Файл run.py в корне проекта добавляет путь к проекту в sys.path, импортирует функцию main из src.db.main и вызывает ее. Это обеспечивает возможность запуска приложения из корневой директории.

Файлы init.py в пакетах db и backend делают эти директории пакетами Python. В init.py пакета db также определен список all, который явно указывает, какие имена экспортируются при импорте пакета. Это позволяет использовать конструкцию "from src.db import *" для импорта основных классов и исключений.

Взаимодействие между модулями построено следующим образом: main.py импортирует ConsoleInterface из tui.py, tui.py импортирует Database из backend.memory и исключения из backend.exceptions, memory.py импортирует исключения из exceptions.py, utils.py является независимым и может использоваться любым модулем при необходимости.

При запуске программы пользователь попадает в главное меню с тремя пунктами: управление таблицами, работа с записями и выход. При выборе управления таблицами открывается соответствующее подменю, где можно создавать, выбирать, просматривать, переименовывать, удалять и очищать таблицы. При выборе работы с записями сначала проверяется наличие выбранной таблицы, затем открывается подменю с операциями над записями: добавление, просмотр всех, поиск по ID, расширенный поиск, обновление и удаление. При добавлении записи можно не указывать идентификатор - он сгенерируется автоматически. При поиске можно комбинировать различные фильтры для точного нахождения нужных записей. При обновлении и удалении сначала показывается текущая запись для подтверждения, что предотвращает случайные изменения. Все действия защищены от некорректного ввода и обрабатывают возможные исключения, выводя понятные сообщения об ошибках.

Проект полностью соответствует структуре, описанной в методичке, но содержит дополнительные улучшения, повышающие его функциональность и удобство использования. Автоматическая генерация идентификаторов избавляет пользователя от необходимости придумывать уникальные ID. Расширенная валидация данных предотвращает сохранение некорректной информации. Возможность переименования и очистки таблиц дает больше гибкости в управлении. Поиск по ID обеспечивает быстрый доступ к конкретным записям, а расширенный поиск с поддержкой произвольных фильтров позволяет гибко находить нужные данные. Подтверждение опасных операций, таких как удаление таблицы, очистка таблицы или удаление записи, защищает от случайной потери данных. При этом код остается читаемым, хорошо структурированным и соответствует стандартам PEP 8, что облегчает его понимание и дальнейшее развитие.
